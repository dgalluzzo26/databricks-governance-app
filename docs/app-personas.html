Who uses the Data Governance app

Three personas share one app. Each sees only the pages their role allows, and the same request flow ties them together.

User

4 sidebar entries

Anyone signed in. Works out what a table needs and asks for it.

  • See which columns are masked and which row filter applies on a table
  • Request data-access, sensitivity, or row-filter attributes, with a justification
  • Track own requests, attributes, and groups under Identity
  • Open Help

Approver

6 sidebar entries

Assigned by an admin to a sensitivity category, a data-access path, or a row-filter dimension.

  • Decide new requests and renewals routed to them in Approvals
  • See who holds a path in Attribute explorer and revoke access
  • Grant values directly on the paths they own, under Identity, Assignments
  • Everything a user can do

Admin

16 sidebar entries

Members of the configured admin group. Owns configuration and the sync.

  • Define attributes, approvers, and their routing
  • Manage policies, exceptions, mask rules, and row-filter packs
  • Run and review the data-access grants sync
  • Read usage, access reports, and sync health in Data access analytics
  • Set app settings, check status, and run performance and recovery

How a request moves

User requests → Routed to most specific approver → Admin if none matches → Approved with expiry → Enforced as UC group, grant, mask, or row filter
Routing rule. The most specific match wins. If finance.budget has its own approver, its requests go there rather than to finance.
